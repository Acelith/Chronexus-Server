# Chronexus Server 0.1.0

The first release of the optional, self-hosted companion for Chronexus 0.9.0 and later. It is
Apache-2.0 licensed, offline-first for the desktop (the app works without it), and keeps your
campaigns on a machine you control. No telemetry, no cloud AI, no third-party service.

**What it does**
- Invitation-only accounts (Argon2id, hashed tokens, persistent attempt limits, device sessions).
- Campaigns with owner, player and reader roles, one-use invitations, versioned memberships.
- Private-by-default content: pages, sessions, relationships, party members, selected character
  sheet sections and managed images (PNG/JPEG/WebP, original bytes, checksums).
- Continuous replication for the desktop: incremental sync with fail-closed cursors, idempotent
  writes with verifiable request IDs, content-free change notifications, conflicts returned with
  both versions.
- Revocation and deletion: removing a member, deleting your server copy, deleting a campaign (by
  its exact name) or your account; former members are told, nothing local is touched.
- Operations: `invite`, `recover`, `revoke-sessions`, `compact`, `backup`, `verify`, `restore`,
  automatic pre-upgrade copies, health checks, a generated OpenAPI contract.

**Run it**: copy `.env.example` to `.env`, set `CHRONEXUS_DOMAIN`, then
`docker compose --profile https up -d --build` (bundled HTTPS) or `docker compose up -d --build`
behind your own proxy. See `docs/INSTALLATION.md`.

**Verified (Windows x64, Rust 1.99.1):** 71 integration tests (authorization matrix over every
campaign route, hostile inputs, backup/restore and failed-upgrade recovery, lifecycle, sync and
notifications), rustfmt, Clippy with warnings denied, a locked release build and the OpenAPI drift
check; the real Chronexus 0.9.0 client engine ran against this server over loopback HTTP
(two computers aligned with about 160 ms median latency, server restart recovery, conflicts,
revocation, deletion, shared images and sections).

**Not verified, so not claimed:** the Docker image and the compose files (Docker was unavailable:
no image is published and the compose/Caddy files were only reviewed), Linux and macOS, ARM64, a
real TLS deployment, vulnerability scans of dependencies and images, third-party penetration
testing, and load beyond the built-in limits.

**Assets:** the Windows x64 executable built from the tagged source, with its SHA-256. Other
platforms: build from source with the pinned toolchain in `docs/DEVELOPMENT.md`.
